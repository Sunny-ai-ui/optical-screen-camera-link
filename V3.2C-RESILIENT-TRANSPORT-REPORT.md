# V3.2C Resilient Multi-Frame Transport

## Goal

Make the V3 optical link tolerant of complete missed optical frames without changing the existing S4C4 optical modulation, temporal fusion, RS(15,11), interleaving, or adaptive profile logic.

## Architecture

The sender now supports two transport modes:

- **Resilient Fountain** — default for V3. Source data is split into fixed-size source blocks. The sender emits systematic source droplets plus deterministic redundant XOR droplets.
- **Classic DATA/END** — retained unchanged for compatibility and A/B tests.

Each fountain droplet is still wrapped in the existing packet layer and therefore retains the per-packet CRC. It is then protected by the existing V3 RS/interleaving optical envelope.

Receiver order:

`camera observation -> temporal fusion -> RS -> packet CRC -> fountain reassembler -> whole-transfer CRC -> recovered data`

RS repairs damaged symbols inside an optical frame. Fountain reconstruction repairs missing complete optical frames.

## Fountain format

Each FOUNTAIN packet payload contains:

- fountain magic/version
- equation degree
- source block count
- source block size
- original byte length
- whole-transfer CRC32
- droplet ID / deterministic seed material
- XOR-coded block data

The first K droplets are systematic source blocks. Additional droplets are deterministic XOR equations over source blocks. The receiver first uses peeling and then a GF(2) linear-system fallback when peeling stalls.

## Sender

V3 defaults to **Resilient Fountain**. A Classic transport selector remains available. The sender currently emits 100% redundant droplets in addition to systematic source droplets; this is intentionally conservative for physical validation and can be tuned after measurement.

## Receiver

The receiver auto-detects whether the current session is Classic or Fountain from the packet frame type. It never mixes transport modes within one session. New diagnostics show:

- transport mode
- unique fountain droplets
- recovered source blocks
- fountain progress

Exact duplicate optical packets remain safely ignored.

## Validation

Added deterministic tests for:

- basic fountain round trip
- missing systematic droplets
- out-of-order droplets
- duplicate droplets
- deterministic equation reconstruction
- V3 G32 optical encode/decode with 20% complete frame loss

The project also includes `npm run benchmark:v3-fountain` to compare recovery at several whole-frame loss rates.

## Important limitation

This phase is still one-way. The sender does not receive acknowledgements from the receiver and therefore emits a finite deterministic droplet set which loops during playback. A later feedback-channel phase could reduce redundancy and retransmit only when needed.
