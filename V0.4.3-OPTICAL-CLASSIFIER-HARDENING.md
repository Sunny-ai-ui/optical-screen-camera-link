# v0.4.3 Optical Classifier Hardening

This release targets the physical G32 failure mode where locator tracking, timing and signature are strong but some RS(15,11) codewords still fail.

## Receiver changes

- Replaced dense per-pixel chromatic sampling with a robust normalized multi-sample estimator that rejects low-saturation glyph pixels.
- Preserves cell-by-cell confidence instead of multiplying every cell by one global channel penalty.
- Refines only the weakest cells at nearby sub-pixel offsets (±0.75 px), capped to bound phone CPU cost.
- Fixes temporal runner-up selection when the winning state is zero.
- Preserves second-best optical symbol candidates through temporal fusion.
- When RS identifies a failed codeword, retries only that block using bounded runner-up substitutions before rejecting the frame.
- Exposes local refinement rate, selective retry count, rescued RS blocks and the weakest cells in the failed codeword.

## Safety and compatibility

- Sender remains unchanged.
- Link remains strictly one-way.
- V3 optical wire format is unchanged.
- RS(15,11), interleaving, fountain transport and v0.4.2 payload format are unchanged.
- Selective retries are bounded: at most six candidate cells per failed block, single substitutions first, then a small pair search.

## Physical test target

Use G32 at roughly 14–18 camera pixels/cell. The desired progression is:

1. Temporal attempts > 0.
2. RS selective retries > 0 on difficult frames.
3. RS rescued blocks becomes non-empty on recoverable frames.
4. Optical decodes > 0.
5. Unique packets > 0.
