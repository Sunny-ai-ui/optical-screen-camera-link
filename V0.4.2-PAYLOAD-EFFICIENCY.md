# v0.4.2 Payload Efficiency and Integrity

This phase adds a payload layer above the existing optical transport without changing V3 optical symbols, RS(15,11), interleaving, temporal fusion, or fountain coding.

## Sender

- Converts text to UTF-8 bytes.
- Evaluates gzip when the browser supports CompressionStream.
- Uses gzip + SHA-256 only when the complete self-describing envelope is smaller than direct UTF-8.
- Keeps short text as direct UTF-8 to avoid hash/compression overhead.
- Displays payload mode and SHA-256 prefix when an envelope is used.

## Receiver

- Detects the self-describing payload envelope automatically.
- Decompresses gzip payloads.
- Verifies SHA-256 before showing recovered text.
- Continues to support older/raw transfers transparently.
- Shows payload codec and integrity mode in receiver metrics.

## Integrity layers

1. Packet CRC32 protects individual protocol packets.
2. Fountain transfer CRC32 protects the reconstructed transport byte stream.
3. SHA-256 protects the original uncompressed payload when the compressed envelope is used.

Short direct payloads use the existing CRC layers because adding a full 32-byte digest would make small messages larger.

## Compatibility

- No reverse communication channel.
- No V3 wire-format change.
- No fountain-format change.
- Legacy raw text remains readable.
