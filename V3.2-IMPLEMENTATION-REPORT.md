# V3.2 Temporal Receiver — Implementation Report

## Implemented

- Split V3 optical classification from RS packet recovery.
- Added ImageData-compatible observation API for worker execution.
- Added Web Worker V3 observation decoder.
- Added temporal observation grouping with profile isolation and transition detection.
- Added independent confidence-weighted shape and colour fusion.
- Added fused confidence stream for existing RS erasure logic.
- Added progressive RS retry as additional compatible observations arrive.
- Added frame-quality gate using timing, signature, pixels-per-cell and confidence.
- Increased receiver sampling cadence in temporal mode while preserving legacy mode.
- Scheduled camera sampling before waiting for worker classification so capture/tracking can continue while decoding.
- Added temporal diagnostics to receiver UI.
- Added V3 single-frame rollback via `?mode=legacy`.
- Added user-triggered debug ROI PNG + diagnostics JSON export.
- Added temporal benchmark command and documentation.
- Bumped project version to 0.3.0.

## Validation

- Baseline before changes: 165/165 tests passed.
- Final suite: 172/172 tests passed.
- Added deterministic temporal-fusion and quality tests.
- Synthetic temporal benchmark intentionally makes three individual observations RS-uncorrectable; fused evidence recovers the exact packet with zero remaining RS corrections.

## Benchmark command

```bash
npm run benchmark:v3-temporal
```

## Physical test

1. Serve the repo from localhost/HTTPS.
2. Sender: choose `V3 Robust · 32×32` and `1 fps`.
3. Receiver: open `apps/receiver-v3/` (temporal mode is default).
4. Watch `Observation group`, `Frame quality`, `Cell agreement`, `RS frame rejects`, `Temporal successes`, and `Decode latency`.
5. If a failure is repeatable, press `Save Debug Snapshot`; share the PNG + JSON for replay/tuning.
6. Compare against `apps/receiver-v3/?mode=legacy` under the same geometry.

## Deliberately not changed in this release

- V3 wire protocol remains compatible with the existing sender.
- No fountain-code transport was introduced yet.
- No new optical frame header was added; transition protection currently uses protected-envelope identity agreement.
- G32/G48/G64 geometry, RS(15,11), interleaving and protocol CRC are unchanged.

Those transport-level changes are intentionally separated from receiver stabilization so real camera evidence can show whether temporal fusion solves the current decoding bottleneck before changing the wire format.
