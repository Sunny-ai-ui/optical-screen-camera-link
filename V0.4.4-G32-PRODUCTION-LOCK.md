# v0.4.4 G32 Production Lock

The current production optical path is intentionally fixed to **V3-G32-S4-C4-RS15-11**.

## Why

Physical testing has already completed real end-to-end G32 fountain transfers with verified payload recovery. Automatic density switching to G48/G64 introduced avoidable instability, frame transitions and lower camera pixels/cell.

## Runtime policy

- Sender exposes only G32 for the live V3 path.
- Sender code returns G32 even if an old page state attempts another profile value.
- Receiver starts on G32 and probes only the G32 signature.
- Runtime density switching is disabled.
- Adaptive link logic may tune evidence requirements but cannot recommend a different density when the production lock is enabled.
- Link optimizer may tune dwell and fountain redundancy while keeping G32 fixed.
- G48/G64 codec implementations remain in the repository for future controlled experiments.

## Unchanged

- one-way communication
- RS(15,11)
- temporal fusion
- local classifier refinement
- RS selective retry
- fountain transport
- adaptive payload compression and integrity verification

This lock is deliberate and temporary. Higher-density modes should only return after G32 reliability and performance targets are measured and repeatable.
