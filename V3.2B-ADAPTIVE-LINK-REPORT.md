# V3.2B Adaptive Optical Link

## Scope

This release builds on V3.2 temporal fusion without changing the optical wire format. It adds receiver-side channel learning, adaptive evidence collection, profile upgrade/fallback recommendations, and profile-aware sender dwell defaults.

## Receiver changes

- Added `apps/receiver-v3/adaptive-link.js`.
- Maintains a rolling channel-quality window from frame quality, cell agreement, classification confidence, pixels-per-cell, decode success, and RS correction load.
- Dynamically selects a target of 1, 2, 3, 4, or 6 observations before RS decode.
- Uses hysteresis before recommending profile changes:
  - sustained poor evidence -> recommend fallback G64 -> G48 -> G32;
  - sustained clean decoding -> recommend upgrade G32 -> G48 -> G64.
- Does not mix or automatically switch the sender profile; the physical link is still one-way.
- Receiver diagnostics now display link quality, evidence target, adaptive action, recommended profile, and good/bad streak.

## Sender changes

- Added `apps/sender-web/adaptive-dwell.js`.
- Added `Auto Reliable dwell` as the default rate mode.
- Current safe dwell defaults:
  - G32: 700 ms/frame
  - G48: 900 ms/frame
  - G64: 1200 ms/frame
- Manual 0.5/1/2 fps remains available.

## Safety / compatibility

- Existing V3 frame format unchanged.
- Existing G32/G48/G64 profile definitions unchanged.
- Legacy `?mode=legacy` receiver remains available.
- No bidirectional feedback is claimed or simulated.

## Next physical-validation step

1. Start sender at G32 + Auto Reliable dwell.
2. Start temporal receiver.
3. Observe link-quality score, evidence target, RS load, and profile recommendation.
4. When receiver holds an `upgrade` recommendation for G48, manually select G48 on sender.
5. Repeat before G64.
6. If receiver shows `fallback`, return to the recommended lower-density profile.
7. Save a Debug Snapshot for any persistent failure.
