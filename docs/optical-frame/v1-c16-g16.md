# V1 Optical Frame — G16 / C16

## Purpose
This is the first deliberately slow and robust optical frame profile for the screen-to-camera project.

## Logical ROI
- Logical ROI: **256 × 256**
- Cell size: **16 × 16** logical pixels
- Grid: **16 × 16 = 256 cells**
- Physical rendering may scale the ROI larger without changing the logical protocol.

## Colour alphabet
Profile `C16` uses 16 provisional colour regions/symbols.

- 16 symbols
- 4 bits per symbol
- two symbols encode one byte

The current RGB values are transmitter reference colours only. A future camera decoder must use the calibration row and classify received colours by region/nearest reference rather than require exact RGB equality.

## Layout

```text
Rows 0-1     Finder/orientation area + guard
Row 2        16 calibration cells: symbols 0..15
Rows 3-13    DATA: 11 × 16 = 176 symbols
Rows 14-15   Finder/orientation area + guard
```

Four 2×2 finder patterns occupy the corners. The patterns are intentionally different so a future vision decoder can determine orientation.

## Data capacity

```text
176 data symbols
× 4 bits/symbol
= 704 bits
= 88 bytes per optical frame
```

The first 2 bytes of the optical data area contain the encoded protocol-packet length.

Therefore:

```text
88 byte optical data area
- 2 byte optical length prefix
= 86 byte maximum serialized protocol packet
```

The current protocol packet has 14 bytes of packet/header/CRC overhead, so the recommended DATA payload is:

```text
86 - 14 = 72 bytes
```

This is why V1 uses a **72-byte protocol chunk size**.

## Optical frame envelope

```text
2 bytes     packet length, unsigned big-endian
N bytes     serialized protocol packet
remaining   zero padding
```

The complete 88-byte envelope is split into high/low nibbles and converted to 176 C16 symbols.

## Outer ROI indication
The SVG renderer currently adds:
- a white quiet zone outside the logical ROI;
- a black rectangular border around the 256×256 ROI.

This is intended to make the first physical camera tests easier. The vision implementation can later replace/refine this with a more robust finder strategy.

## Current status
Implemented:
- C16 nominal constellation;
- byte↔C16 symbol conversion;
- packet→optical frame mapping;
- ideal optical frame→packet mapping;
- SVG rendering;
- browser sender preview;
- automated round-trip tests.

Not implemented yet:
- camera capture;
- ROI detection from real images;
- perspective correction;
- colour calibration from camera measurements;
- nearest-colour classification;
- confidence/erasure handling.
